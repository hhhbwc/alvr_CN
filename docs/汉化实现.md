# ALVR 简体中文汉化（v21 主线）

把 ALVR 的 **PC 端面板（Dashboard）和启动器（Launcher）** 变成简体中文。

针对 **当前主线 `21.0.0-dev14`**（`alvr-org/ALVR` master），不是已经停更的 v20 稳定版。

## 为什么要重做

现有方案都停在旧版本，且都不完整：

| 方案 | 状态 | 问题 |
|---|---|---|
| `Jimmy32767255/ALVR-CN`（CN-GUI 分支） | 2025-08 停更 | 基于 v20.13，落后主线 60+ 提交；**没有任何 release**，要自己编译；部分中文还被回退成英文 |
| `juchaoo/alvr-cn-tool` + 预编译包 | 2026-07 | 只到 v20.14.1；翻译 498 条，设置面板的自动名称覆盖不全；工具绑定源码树，每次升级要重跑 |
| 本项目 | v21 主线 | 覆盖 220 个设置项 + 81 个枚举 + 66 段帮助 + 85 条界面文案，一键重打 |

## 实现方式

ALVR 的界面是 Rust + egui 原生绘制，**没有任何 i18n 框架**（`dashboard/Cargo.toml` 里连 `rust-i18n`/`fluent` 都没有），文案全部硬编码在 `.rs` 里。所以汉化只能改源码，本项目做的是「可复现的源码补丁」：

1. **词表驱动**：所有中文放在 `translations/*.json`，用脚本生成 `alvr/gui_common/src/zh_cn.rs`（编译期 `match` 查表，无运行时 IO、无新依赖）。
2. **按路径取词**：在 `settings_controls/mod.rs` 加 `get_display_name_localized()`，用 `video.bitrate.mode` 这种完整路径查中文。这样连**没有显式 `display_name` 的设置项**（例如 `bitrate_bps` 由字段名自动生成 "Bitrate bps"）也能翻译，不必逐个改源码。
3. **枚举选项**：`choice.rs` 里同样按 `父路径.变体名` 查表（`video.preferred_codec.Hevc` → HEVC）。
4. **界面字面量**：`ui.label("…")` / `ui.button("…")` 之类包一层 `zh_cn::tr(…)`，共 79 处。
5. **中文字体**：`theme.rs` 的 `set_theme()` 里注册 Noto Sans SC 子集（**156 KB**，734 个字形）。egui 默认字体没有中文，不注入就是满屏豆腐块；而**子集必须跟着词表重建**——第一版就是忘了这步，导致「安**□**」这类新翻译的字变成空心方框。现在 `apply.py` 每次打补丁前都会从 `fonts/NotoSansSC-Regular.otf` 重新裁剪，`verify.py` 还会逐字校验 cmap。

## 目录

```
alvr-cn/
├── tools/
│   ├── catalog.py      # 解析 settings.rs → 带路径的设置项清单
│   ├── build_dict.py   # 合并词表 + 校验（路径写错会直接报错）
│   ├── font.py         # 裁剪 Noto Sans SC 子集
│   ├── apply.py        # 把词表打进源码树（幂等，可反复执行）
│   └── verify.py       # 不编译的静态自检（括号配平、分支数、依赖）
├── translations/
│   ├── names.json      # 路径 → 中文名（220 项 + 枚举）
│   ├── helps.json      # 路径 → 中文帮助（66 段）
│   ├── ui.json         # 英文原文 → 中文（界面文案）
│   └── zh-CN.json      # 上面三个合并后的产物，apply.py 读它
├── fonts/NotoSansSC-Subset.otf
└── patch/alvr-21.0.0-dev14-zh-CN.patch   # 生成好的 diff，可直接审阅
```

## 用法

```bash
git clone --depth 1 https://github.com/alvr-org/ALVR.git alvr-src
cd alvr-src

python ../alvr-cn/tools/catalog.py --src . --out ../alvr-cn/catalog.json
python ../alvr-cn/tools/build_dict.py --catalog ../alvr-cn/catalog.json --dir ../alvr-cn/translations
python ../alvr-cn/tools/apply.py --src . --dict ../alvr-cn/translations/zh-CN.json
python ../alvr-cn/tools/verify.py
```

然后编译（Windows）：

```
# 前置：rustup、VS2022「使用 C++ 的桌面开发」+【必须】ATL 组件、LLVM
git submodule update --init --recursive
cargo xtask prepare-deps --platform windows --ci
cargo xtask build-streamer --release --gpl
# 产物：build/alvr_streamer_windows/
```

## 实测：已编译并运行验证

本机（RTX 4060 Laptop / Windows 11）已完整跑通，产物在
`alvr-src/build/alvr_streamer_windows/`（293 MB：`ALVR Dashboard.exe` +
`bin/win64/driver_alvr_server.dll` + FFmpeg 全家桶 + `openvr_api.dll`）。
截图见 `截图-设置页.png`、`截图-设备页.png`。

实测踩到的三个坑：

1. **必须装 VS 的 ATL 组件**（`Microsoft.VisualStudio.Component.VC.ATL`）。
   `VideoEncoderVPL.cpp` 引了 `atlbase.h`，缺它会让所有 C++ 编译以 `exit code 2`
   失败，而且 **cl.exe 一个字都不报**（只能看到 cc-rs 说命令失败）。NVIDIA 用户
   也躲不开，因为 VPL 那段代码没有 `#ifdef` 保护。
2. **可以完全不用管理员权限装机**：rustup 装用户目录；LLVM 只取
   `libclang.dll`（从官方 `clang+llvm-*-x86_64-pc-windows-msvc.tar.xz` 单独解出，
   设 `LIBCLANG_PATH`）；`prepare-deps --ci` 会跳过 Chocolatey；编译前必须
   `call vcvars64.bat` 否则 cc 找不到 `INCLUDE`/`LIB`。`build.bat` 已封装这些。
3. 出包时 `ALVR Dashboard.exe` 不能正在运行，否则复制报 `os error 32`。

## 更新到新版本

1. 重新跑 `catalog.py`；
2. 跑 `build_dict.py`，它会列出**新增但没翻译**的条目；
3. 往 `names.json` / `helps.json` / `ui.json` 补翻译；
4. 重跑 `apply.py`。已翻译的部分不会重复劳动。

## 已知边界

- **头显端 App 不需要汉化**：ALVR 客户端在头显里基本没有 UI，设置全在 PC 面板上。
- **预设下拉的「值」已汉化**（`中（宽 4288）`、`速度优先/均衡/画质优先`、`轻/中/高`）。
  做法是：`name`（写回 `session.json` 的 `variant` key）保持英文，只把 `strings["display_name"]`
  过一层 `tr()`，所以界面是中文而落盘数据仍然正确。
- 仍保留英文的：`60Hz/72Hz/…` 之类的数值、`H264/HEVC/AV1` 编码器名、
  `VoiceMeeter/VB Cable` 等软件专名、`session_log.txt` 运行日志。
- **带 `{}` 的格式串保持英文**：`format!` 的参数必须是字面量，塞函数调用会编译失败，这类留给后续用 `format!` 拆分处理。
- **日志、错误弹窗** 里由 `anyhow` 抛出的长句仍是英文。

## 许可

- 补丁与词表：跟随 ALVR 的 MIT。
- 字体：Noto Sans SC，SIL Open Font License 1.1，可再分发（这一点比某些分支直接打包「微软雅黑」安全）。

## 头显端（Android APK）

头显里不是没有文字——连接时会显示一块 HUD：

```
正在搜索串流端…
请在电脑上打开 ALVR，然后点击设备条目右侧的「信任」
```

（上面还会显示 `ALVR v21.0.0-dev14 / 主机名 / IP`）

实现要点：

1. **字体**：HUD 由 `alvr/graphics/src/lobby.rs` 用 `glyph_brush_layout` 绘制，原本只嵌了
   `Ubuntu-Medium.ttf`（无汉字）。改成两套字体做回退：
   `calculate_glyphs(&[&ubuntu_font, &cjk_font], ...)`，绘制时按 `section_glyph.font_id`
   选对应的缩放字体。CJK 字体就是上面那份 Noto 子集，复制成 `resources/NotoSansSC-HUD.otf`。
2. **文案**：常量留在 `client_core/src/connection.rs` 保持英文（日志用），
   新增 `zh_hud()` 按常量比较返回中文，只在 `set_hud_message()` 里替换显示内容。
   动态的 `Connection error:` 也一并改成中文前缀。
3. **应用名**：`client_openxr/Cargo.toml` 的 `label` 改为 `ALVR 客户端`。

### 编 APK 时踩的坑

- `cargo-apk` 读的是 `targetSdkVersion = 32`，SDK 里必须装 `platforms;android-32`
  （本机原来只有 34/35/37）。
- **上游的 OpenXR loader 下载地址已失效**：`xtask` 里把版本钉在
  `1.1.36`，而 Khronos 那边这个 release 的资源已经 404，`unzip` 直接报
  "cannot find zipfile directory"。绕法：从官方 nightly APK 里取
  `lib/arm64-v8a/libopenxr_loader*.so`（Pico 4 用的是 `_pico_old` 那个），
  放进 `deps/android_openxr/arm64-v8a/`，然后跳过 `prepare-deps` 直接 build。
- 产物：`build/alvr_client_android/alvr_client_android.apk`（27 MB，
  包名 `alvr.client.dev`，debug keystore 签名）。

⚠️ 因为签名是自签的 debug key，与官方包不同，**装之前要先卸载头显上的官方 ALVR 客户端**，
否则会报 `INSTALL_FAILED_UPDATE_INCOMPATIBLE`。

```bash
adb uninstall alvr.client.dev
adb install -r build/alvr_client_android/alvr_client_android.apk
```
